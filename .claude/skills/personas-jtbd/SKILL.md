# Personas and jobs-to-be-done

## Purpose
Make decisions from what users need, not what the team assumes.

## Procedure
1. Gather evidence: the brief, reviews of competing products, forum threads, support tickets, any interviews. Label each insight with its source; label guesses as assumptions.
2. Write 1–3 proto-personas: context, goals, frustrations, constraints (device, time, skill, accessibility needs). No stock-photo fluff.
3. Write JTBD statements: "When [situation], I want to [motivation], so I can [outcome]." Add functional, emotional and social dimensions.
4. Journey map for the main job: stages → actions → thoughts → feelings → pain points → opportunities.
5. Prioritise opportunities by frequency × severity.
6. Draft a 5-task usability-test script (scenario, task, success criteria, follow-up questions) for 5 participants.

## Checklist
- [ ] Every persona trait links to evidence or is marked as an assumption.
- [ ] JTBD statements describe situations, not features.
- [ ] Journey includes before and after the product is used.
- [ ] Accessibility needs are represented.

## Output template
## Evidence · ## Personas · ## Jobs to be done · ## Journey map (table) · ## Opportunities (ranked) · ## Test script
