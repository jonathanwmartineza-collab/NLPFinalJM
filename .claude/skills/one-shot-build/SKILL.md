# One-shot build: a complete page in one file

## Purpose
Ship a finished, good-looking, working single-file app on the first attempt: something a person can open, use, and publish after a review. It must run inside a strict sandbox (no network, no external scripts).

## Procedure
1. Read the brief and, if present, the one-shot-spec JSON. If no spec exists, write a 10-line mental spec first: audience, sections/screens, features, states, palette, type, layout.
2. Pick one visual idea from the subject's own world (a menu, a ticket, a dashboard instrument, a field guide) and carry it through colour, type and layout. Avoid generic templates (centered hero + three cards + gradient).
3. Write the document in this order: comment line, `<!DOCTYPE html>`, `<html lang>`, head (charset, viewport, title, description, inline `<style>`), body (landmarks: header, nav if needed, main, footer), inline `<script>` last.
4. Style with CSS custom properties: `--bg --ink --soft --line --accent --accent-ink` plus dark values in `@media (prefers-color-scheme: dark)`. Use a 4px spacing scale, one type scale (4 sizes), `clamp()` for big headings, `minmax(0,1fr)` grids, and `flex-wrap` so nothing overflows at 360px.
5. Write real content: names, numbers, prices, dates and copy that fit the brief. Never lorem ipsum. Mark sample data once, quietly ("Sample data").
6. Make interactions real: forms validate and show inline errors; lists filter/sort; buttons do something; state persists in `localStorage` only inside try/catch. Every async-looking action has loading, empty and error states.
7. Accessibility: labels for every input, visible `:focus-visible`, 24px+ targets, contrast 4.5:1 text / 3:1 UI, `aria-live="polite"` for status messages, `prefers-reduced-motion` turns off animation, alt text or `aria-hidden` on decorative SVG.
8. Images: inline SVG illustrations or CSS gradients; no remote images. Fonts: system stack, or Google Fonts via `<link>` (optional; must look fine if blocked).
9. No `fetch`/XHR/WebSocket, no external `<script src>`, no `eval`, no tracking. If the brief needs data from an API, simulate it with local sample data and say so in a comment.
10. Run the checklist below, fix, then output only the document.

## Checklist
- [ ] First line is `<!-- AI-generated by BrainyApp2; review before publishing -->`, then `<!DOCTYPE html>`; the file ends with `</html>`.
- [ ] One file; inline CSS and JS; no external scripts, no network requests, no remote images.
- [ ] Responsive from 360px to 1440px with no horizontal scroll; tap targets at least 24px.
- [ ] Light and dark themes via CSS variables and `prefers-color-scheme`; both readable.
- [ ] Text contrast at least 4.5:1, controls and focus rings at least 3:1; visible keyboard focus everywhere.
- [ ] Landmarks (header/main/footer), one h1, logical heading order, labelled form fields.
- [ ] Realistic, specific content; no lorem ipsum, no fake testimonials presented as real people.
- [ ] Empty, loading and error states where the UI has data or forms.
- [ ] `prefers-reduced-motion` respected; animation only where it explains something.
- [ ] JavaScript wrapped to avoid globals, runs after the DOM, no console errors.
