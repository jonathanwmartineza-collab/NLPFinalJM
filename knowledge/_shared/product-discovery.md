# Product discovery toolkit
Why this matters: build the right thing before building it right.

- Jobs-to-be-done: "When [situation], I want to [motivation], so I can [outcome]."
- PRD essentials: problem, users, goals and metrics, MVP scope (MoSCoW with an explicit Won't), user stories with Given/When/Then acceptance criteria, non-functional requirements, risks.
- Metrics: one north-star metric, 3–5 input metrics, guardrails (errors, latency, cost, complaints); event names `object_action`; no personal data in events.
- Experiments: pre-registered hypothesis, primary metric, minimum detectable effect, sample size, fixed duration (at least one weekly cycle), decision rule.
- Usability tests: in qualitative rounds with one user group, about 5 participants find most major issues (a rule of thumb, contested for varied audiences and quantitative goals); test tasks, not opinions.

Sources: https://www.nngroup.com/articles/why-you-only-need-to-test-with-5-users/ (accessed 2026-11-21); https://www.productplan.com/glossary/moscow-prioritization/ (accessed 2026-11-21)
